# Steam 最近一代代码复用（实验性）

此实现位于 mdeck 自有 FEX 补丁 0007，FEX 子模块及 pin 不变。默认关闭；当前只完成源码实现，尚未执行本轮 Actions 检查、完整 PE 编译或实机验证，不能据此宣称稳定性或性能收益。

## 开关与范围

Steam 设置 → 高级 → 性能 →「上一代代码复用（实验性）」。配置键为 `env.MADEIRA_FEX_PREVIOUS_CODE`，只有精确值 `1` 开启；配置项继承全局值，Steam 配置可覆盖。下次启动生效，启动中或运行时不可修改。

WoW64、ARM64EC 各自初始化时，以当前进程映像 basename `steamwebhelper.exe` 判定 CEF，并冻结选择。其他映像即使继承配置也不开启。选择在 `InitCore` 前完成，与编译原因日志、DFE 临时存储复用和 L1 索引开关独立；宿主在应用新配置前清理旧环境值，避免跨会话遗留。启动日志为 `[fex-prev] path=... mode=on|off target=cef|other previous-budget-mib=128`。

## 查找及执行所有权

原有当前代 L1/L2/L3 查找先执行。只有 dispatcher 的普通 miss 才进入新增查找：按最新代、最近上一代的顺序检查，跳过线程已经所属的代。仅接受正常发布的条目：`MaxInst == 0`、非 TF、具备普通 guest executable-range 元数据；自定义 IR、单步、未发布的 delivery 编译不作为复用入口。存在异常处理引用、当前线程持有输出锁或处于未发布编译时不迁移。

命中后同时切换 `CurrentCodeBuffer` 和线程 `Shared` 映射，清理 L1/L2 与 call/ret 预测，再在目标代读锁内重新确认 HostCode 身份及正常条目资格，使用现有 `CacheBlockMapping` 回填代码页和缓存。不会将某代 HostCode 注册到另一代 L3。目标条目被并发发布替换时放弃本次命中；线程所属代可能已经切换，随后走正常编译路径。

这采用完整缓冲区所有权迁移。活动线程的强引用继续保护正在执行的代码，原有异常 PC 识别仍通过 `CurrentCodeBuffer` / `SignalHandlerCodeBuffers` 工作。后端生成新代码时仍按原机制切换到可写的最新缓冲区，旧代不重新开放追加写入。

锁顺序为外层 `CodeInvalidationMutex` 共享锁、旧映射写锁、线程迁移锁、短暂 `LatestMutex`；候选检查先独立取得并释放候选读锁，不同时持有两张映射锁。迁移前在叶锁内重查该缓冲区仍属于最新/上一代候选。

## 不新增跨代持久链接

开启时，退出链接器遇到 miss 先返回 dispatcher，避免在旧代返回 thunk 仍在宿主调用栈时做向后迁移。安装持久链接前同时检查源 `Record` 和目标 HostCode 属于线程当前缓冲区；不满足则回到 dispatcher。同代既有链接机制保留。

这可能增加 dispatcher 往返，以及在两代间切换时的 L1/L2 清理成本。命中次数不等于避免编译次数或净节省时间，必须用实机耗时与 CPU 数据验证。

## 保留与回收

每个启用实例的 CodeBufferManager 只增加一个上一代强引用，限该缓冲区 `AllocatedSize <= 128 MiB`。只有容量不足引起的换代才进入此保留入口。容量原因来自既有 `MDeckReasonRequestBytes` 作用域，该字段的设置不依赖诊断是否开启。

分配新缓冲区前先移除更老的上一代搜索入口，在 `LatestMutex` 外释放该引用；新代成功发布时再保留刚退出的最新代。分配失败期间旧的额外保留入口可能已经撤下。正常执行、异常处理及临时候选快照仍持有的强引用不强制释放。

因此 128 MiB 是**单个 manager 的额外搜索保留预算**，不是整个进程 JIT 内存上限，也不包含映射表开销、其他实例、活动线程或异常必须保留的旧缓冲区。即使不再是最近上一代，线程仍可继续执行自己安全持有的那一代。

显式清缓存（包括非容量原因创建新缓冲区）会停止该 manager 后续复用，直至会话重启；不会再从保留代恢复被显式清除的查找状态。

## 失效边界

沿用现有全进程失效路径：遍历全部存活缓冲区的 L3、清理有关线程的 L1/L2 和页记录，并解除对应的持久链接。保留引用让上一代仍在全缓冲区列表中存活，因此 SMC、保护变化、释放、卸载、指令缓存刷新及地址复用通知也覆盖它。iOS 16 KiB SMC 补丁保持不变。

不以编译原因日志的内容哈希作为安全证据或有效性判定。有效性仍依赖 FEX/Wine 的现有失效通知和热 SMC 校验。外部写入漏通知、并发异常、卸载后同地址重载等情况必须在真实运行时验证；本补丁没有宣称解决现有失效机制之外的写入方式。

## 日志与验证

`[fex-prev] owner=... attempts=... latest_hits=... previous_hits=... misses=... latest_rx=... previous_rx=... retained_bytes=...` 记录累计尝试和命中。前 8 次尝试、之后每 1024 次以及新缓冲区分配后输出。多线程字段以独立原子读取，报告可能不是同一时刻快照；没有最终完整快照保证。`owner` 是会话内 manager 地址；不要跨会话合并。`retained_bytes` 只反映保留入口，不是总存活旧代码内存。
