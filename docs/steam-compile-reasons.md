# 编译原因日志

入口：**Steam 设置 → 高级 → 诊断 → 编译原因日志**。默认关闭，下次启动 Steam
生效。与 CEF 热点检测、CPU、窗口和分配诊断独立；不需要开启热点检测。
运行期间可点 **停止编译原因日志**。手动配置：

```ini
env.MADEIRA_STEAM_COMPILE_REASONS = 1
```

从 Wine 启动起最多 45 秒、每秒汇总，最多记录 400,000 次已完成的编译尝试。
失去前台活动状态、会话结束或手动停止时取消。重新回前台不自动重启；下次启动
Steam 根据保存的开关重新启用。本功能不暂停任何线程。

## 分类与含义

| 字段 | 记录的事实 |
| --- | --- |
| first_observed | 本次观察窗口中，该 PE 实例、代码管理器、guest RIP 和编译模式首次保留了有效指纹记录 |
| changed_content | 与该键的上一条记录相比，解码形状相同，实际解码字节指纹改变 |
| same_content_new_generation | 解码形状和字节指纹相同，输出到了另一代代码缓冲区 |
| same_content_same_generation | 内容指纹相同，输出代也相同，仍再次生成代码 |
| unknown | 解码形状变化、指纹超限/不可用、代信息缺失、历史表探测溢出或并发完成顺序不可靠 |

**这些是编译来源的观察分类，不是因果证明。** 首次观察不等于整个进程生命周期
第一次编译，开始记录前可能已有编译；同内容新代不能单独证明“换代是唯一原因”；
内容变化也不能单独证明是 SMC 写入，还可能是代码映射变化。不会据此复用代码或
改变失效策略。

每个真正进入后端并生成有效入口的调用恰好进入一个分类。其他结果单独计数：
`raced` 为 IR 已生成后复查发现别人编译完成；`failed` 包括未得到 IR 或后端没有
有效入口；`delivery` 为异常投递期间的特殊编译，避免与普通编译混合。

计时从 CompileCode 中的诊断开始，到后端返回有效入口；包含解码、IR 生成/处理、
后端生成和期间等待，也包括指纹成本，叫 `total_wall_ms`，不是 CPU 时间。
不覆盖随后发布映射、日志符号或最终执行翻译代码的耗时，不能直接与其他包含式
计时相加或相减。线程统计按 instance、PID、TID 输出最多 8 个最忙记录；总数覆盖
全部已成功录入尝试，线程表满时由 `thread_overflow` 明示。

## 代码身份和指纹

每个 PE 初始化时取得宿主分配的唯一 instance；每个 CodeBufferManager 和每次
实际 CodeBuffer 分配取得独立序号。生成代码在持有原有写锁、最终输出缓冲区确定
后带回该缓冲区序号，避免用“其他实例刚发生换代”的全局计数代替实际代。
guest RIP、MaxInst、32/64 位和 TF 模式参与身份。不同进程、不同管理器、单步模式
和普通模式不混合。上述序号仅诊断元数据，不修改翻译块布局或跳转链接。

在 GenerateIR 中遍历原有指令时，使用解码器已保存的 InstBytes，避免重新读取
可能改写/解除映射的 guest 代码。顺序、指令地址、长度和基本块边界组成形状指纹；
实际字节组成双 64 位指纹。形状不同先记 unknown，不把多块解码范围变化当成字节
变化。自定义 IR 和超过 16 KiB/2048 条指令的输入不作内容判定。哈希存在碰撞可能，
“相同”指指纹匹配，不能用这份日志作逐字节等价或安全性的证明。

宿主历史表 65,536 槽，每次最多探测 8 槽，不驱逐本窗口内的旧记录。表满/探测冲突
记 `history_full` 和 unknown，不能把淘汰的记录重新算作 first_observed。整个共享
区在宿主首次开启时分配，之后永久保留，使用 epoch 隔离会话；PE 完成旧 scope 不会
写入新会话。锁只尝试一次，竞争或嵌套重入直接丢弃并记录 dropped，不等待。
并发开始和完成顺序倒置记 out_of_order，不用较旧结果覆盖较新基线。

## 导出与分析

```text
[steam-compile-reason]    总体分类、覆盖范围、限制和最终停止原因
[steam-compile-kind]      每类次数、累计/平均/最大经过时间
[steam-compile-thread]    按运行实例和 Windows 线程汇总
```

同一 session 每秒输出累计快照，使用最后一份完整快照或两个快照之差，不能逐秒
相加。总数与线程明细是相同事件的不同视图，也不能相加。`snapshot=busy` 是漏掉
这一轮输出，不代表计数清零。先确认 attached_paths（1=WoW64、2=ARM64EC）、
history_full、shape_changed、dropped、out_of_order、unknown，再判断比例。

建议同时开启轻量性能日志，保持前台运行约 50 秒后导出同一次日志。完整构建、
PE 链接及 iPad 上的日志正确性/开销需要后续打包实测；GitHub Actions 的受控
fixture 仅验证分类逻辑、并发/会话隔离、字节来源和宿主生命周期。
