# Steam 安装向导自动操作

首页首次启动仍使用内置、SHA-256 校验过的官方 `SteamSetup.exe`，不修改安装程序。
由安装器自己的 Wine GUI 线程观察窗口，识别页面稳定 700ms 后向标准 IDOK 按钮
发送 `WM_COMMAND / BN_CLICKED`，相当于点击按钮，不依赖焦点、坐标或固定时间发 N。

顺序为两个不同的“下一步”页面 → 安装目录确认 → “安装” → 安装结束后的“完成”。
仅匹配 `C:\Madeira\Installers\SteamSetup.exe` 的可见、可用 NSIS 对话框；
按钮必须是该对话框直属的 Button/IDOK，页面必须是唯一可见的子对话框。
支持英文 Next/Install/Finish 与简体中文下一步/安装/完成（含快捷键标记）。
同一页面/按钮角色只发送一次，不会因轮询重复跳过页面。
安装按钮还要求可见编辑框的路径为 `C:\Program Files\Steam Client`。
未知页面、错误对话框、目录被更改或按钮不可用时不进行自动点击，用户仍可手动操作。
发送失败三次停止自动操作；不自动确认重装、覆盖文件或关闭错误弹窗。

Steam 安装器和更新器自动启动 `steam.exe` 时，通过既有 `MADEIRA_CHILD_ARGS`
规则补上 `SteamClient.clientArguments` 的兼容参数。它只匹配 steam.exe，
不会给 steamwebhelper 或其他程序附加这组启动器参数。用户已经配置的子进程规则保留。
`MADEIRA_STEAM_AUTOINSTALL=0` 可在会话开始前禁用向导自动操作。
只在 Steam 客户端/安装器会话配置这些环境变量，不修改 Dock 或普通游戏的启动设置。

验证包含真实策略和窗口适配器的受控回归：两次下一步、安装、完成、稳定期、
禁用按钮、错误进程/线程、被禁用的主窗口、安装目录和重复事件，以及现有子进程匹配。
受控窗口快照不是实体 iPad 上真实 NSIS 的验收；新包还需要验证实际页面结构和行为。

Build 16 真机日志没有任何自动按钮动作。核对实际 `NtUserGetClassName` 后发现它返回字符数，
不写入传入 `UNICODE_STRING.Length`，而旧适配器错误地读取了这个保持为零的字段，
导致所有类名匹配失败。旧测试替身填了 Length，掩盖了错误。
修正使用返回的字符数；回归直接编译生产 `class_ios.c` 中的类名读取函数，
确认 Length 保持零时旧判断拒绝对话框、新判断和完整操作流程能通过。
增加会话配置、安装器 GUI 线程启用和窗口结构快照日志，便于定位后续不匹配条件。
