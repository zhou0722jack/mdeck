# Steam 缓存查找优化（试验）

入口：Steam 设置 → 高级 → 性能 → **缓存查找优化（试验）**。
默认关闭，下次启动 Steam 生效。与性能日志、CEF 热点检测分别控制。
使用全局 Steam 配置的游戏继承该设置。手工配置键：

```ini
env.MADEIRA_FEX_L1_HASH = 1
```

`0` 或缺失使用旧索引，只有严格的 `1` 启用。启动日志：

```text
[fex-l1] path=wow64 mode=fold16-v1 cache-bytes=unchanged
[fex-l1] path=arm64ec mode=fold16-v1 cache-bytes=unchanged
```

选择在每个 PE 实例的 InitCore 之前固定；若在设置前已经有人查询策略，则固定为
legacy。已有分派器、编译块与 C++ 缓存实例不能在同一实例中切换索引规则。
UI 在会话运行时禁用该开关；宿主每次会话先清理环境变量，再按全局/游戏配置导出。

## 实现范围

原索引为 `address & mask`，地址低位相同的代码块争用同一缓存槽。
新索引混入更高地址位：

```text
h = address XOR (address >> 16)
h = h XOR (h >> 32)
index = h & mask
```

它只改变槽位选择，命中仍比较完整 guest 地址。现有缓存容量、完整地址校验、
L2/L3 回退、代码生成、代码缓冲区生命周期及同步机制均由原路径管理。
没有新增缓存表，也没有把其他进程或旧代码缓冲区中的指针旁路缓存起来。

四处生成的 ARM64 路径使用同一发射函数：EC 返回快速查找、分派器循环、L2 命中后
回填 L1，以及间接跳转/调用/返回的 L1 查找。新路径比原地址计算多三条指令；只
改写原来的两个 scratch 寄存器，保留 guest RIP、L2 命中的 host 指针和 NZCV。
关闭时生成原来的 LDP/AND/ADD 序列，不在每次跳转上增加开关分支。

C++ 查找、回填和指定地址失效使用同一索引。动态增大/缩小时，失效继续清理所有
可能保留旧条目的容量下的槽位；缩小后的页释放和换代全清仍覆盖实际映射范围。

## 验证与对照

GitHub Actions 验证补丁链、配置隔离、实际生产查找/回填/失效方法，并用生产
ARM64 发射器生成代码，在 ARM64 Mac runner 上执行，核对地址计算、RIP/其他
寄存器与 NZCV 保持。构造低位碰撞序列仅验证机制，不代表 Steam 的性能提升。
完整 PE 构建、IPA 和 iPad 实测需另行明确授权打包后进行。

设备对照应在同一版本中分别关闭/开启，使用相同页面和滚动操作。观察 CEF 线程
CPU、`CompileBlock` 调用率和 `[l1-miss]`；后者为进程级累计统计、会受动态缓存
模式影响。主要流畅度比较时关闭热点检测，必要时单独开启它采集有界诊断。
两条新增 XOR 和额外一次 load 也有成本，因此需要设备测试确认净收益。
